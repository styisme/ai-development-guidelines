## なぜこの仕様が必要か

AI は今や、コンパイル・実行・リリース可能なコードを書くことができます。問題は「AI が書けるかどうか」ではなく、以下の点にあります：

- 問題が発生した際、**誰が責任を負うのか**；
- どの部分が生成され、どの部分がレビューされたのか、**誰も判別できない**；
- リスクの高い機能が AI によって本番環境に組み込まれ、**誰も止められない**；
- 「AI 支援開発」を名乗りながら、**検証可能な開示基準がない**。

本仕様は最小限の約束事を定めます：**人間が意思決定と検収に責任を持ち、AI が生成し、生成されたものは検証・開示・説明可能でなければならない。**

本仕様は AI ツールの優劣を評価するものではなく、特定のモデルを強制するものでもありません。

---

## 基本原則

1. **人間が責任主体である。** AI は著者でも責任者でもない。
2. **生成 ≠ 利用可能。** コンパイル、レビュー、検証が済んでいないコードは未完成である。
3. **リスクと権限は比例する。** 認証、ファイルシステム、コマンド実行、リリースプロセスに近づくほど、レビュー要件は厳しくなる。
4. **デフォルトで安全、デフォルトでオフ。** 高危険度の機能はデフォルトで無効とし、有効化には明示的な確認と記録を要する。
5. **真実を開示する。** 検証プロセスを示せない「すべて AI が作成」よりも、「約 80%」と書く方が良い。

## 仕様

以下のキーワードは [RFC 2119](https://www.rfc-editor.org/rfc/rfc2119) に従って解釈されます：**必須（MUST）**、**推奨（SHOULD）**、**任意（MAY）**。

### 1. 説明責任

1.1 プロジェクトは、マージとリリースに責任を持つ人間のメンテナを少なくとも 1 名**必須**で指定しなければならない。  
1.2 マージ、リリース、データ削除、権限変更などの意思決定は人間が行わ**なければならず**、AI による自動実行を**禁止**する。  
1.3 プロジェクトは、AI が生成に関与し、人間が検収を負うことをドキュメントで**推奨**する。

### 2. 利用範囲

2.1 以下の内容は AI が直接生成**可能**だが、コンパイルと基本的なレビューを要する：ボイラープレート、UI レイアウト、スタイル、ドキュメント草稿、コメント、テスト草稿、ビルドスクリプト。  
2.2 以下の内容は人間による行単位の重点レビューが**必須**である：認証とセッション、暗号化と証明書、パスとサンドボックスの検証、プロトコル解析、コマンド実行、データベースマイグレーション、CI/CD のシークレットとリリーススクリプト。  
2.3 プロジェクトは、実際のシークレット、証明書、トークン、ユーザーデータを公開 AI サービスに送信しては**ならない**。  
2.4 高危険度機能（Root、全ディスクアクセス、リモートコマンド実行、自己破壊、トンネリングなど）はデフォルトで有効にしては**ならず**、セキュリティドキュメントで個別に警告**必須**である。  
2.5 プロジェクトは、開示ドキュメントにおいて AI 関与の割合を過大または過小に報告しては**ならない**。

### 3. 生成とレビュー

3.1 各 AI 生成は、目標、制約、ターゲットプラットフォーム、関連ファイル、エラーログなどの明確なコンテキストに基づく**推奨**。  
3.2 AI 生成コードは、メインブランチに到達する前に人間のレビューを**必須**とする。  
3.3 レビューは少なくとも、論理的正確性、例外処理、依存関係の必要性、プラットフォーム API の実在性、ライセンスの互換性をカバー**推奨**。  
3.4 大規模な生成変更は、追跡とロールバックを容易にするため個別にコミット**推奨**。  
3.5 コミットメッセージに `ai-assisted` とタグ付けするか、PR 説明で AI 関与範囲を明記**可能**。

### 4. 検証

4.1 AI 生成コードは、ターゲットプラットフォームで少なくとも 1 回コンパイルを**必須**とする。  
4.2 プラットフォーム API、権限、UI、バックグラウンド維持、ネットワークに関わる変更は、実機または実環境での検証を**必須**とする。  
4.3 コアロジック（パーサー、パス検証、認証、チャンクアップロードなど）は、再現可能なテストを**推奨**。  
4.4 「AI が問題ないと言った」は検証結論と**ならない**。  
4.5 トリミング、移植、リファクタリング後は、完全なリグレッションを**推奨**。

### 5. 開示

5.1 プロジェクトは、リポジトリに AI 生成声明ファイル（推奨：`AI_DISCLOSURE.md`）を提供**推奨**。  
5.2 開示には、AI 関与範囲、人間の作業、既知の制限とリスク、ライセンス条件を**必須**で含める。  
5.3 関与割合の著しい変化、新高危険度モジュールの追加、新ブランチや移植版の作成、メジャーバージョンリリース時には、開示を**必須**で更新する。  
5.4 開示には最終更新日を**推奨**。  
5.5 開示ファイルはセキュリティドキュメントの代替と**ならない**。高危険度機能は別途ドキュメント化**必須**。

### 6. セキュリティとコンプライアンス

6.1 シークレットと証明書は Secrets または環境変数経由で注入**必須**であり、リポジトリに入れては**ならない**。  
6.2 AI が提案したサードパーティ依存関係を採用する前に、ライセンス、サイズ、メンテナンス状況、セキュリティ記録を評価**推奨**。  
6.3 生成された音声、画像、テキストには、関連するサービス規約と著作権要件を遵守する旨の通知を**必須**で添付する。  
6.4 自己署名証明書、文字列ブラックリスト、クライアントサイド検証を「セキュリティ監査済み」と記載しては**ならない**。

### 7. ドキュメントと追跡可能性

7.1 ドキュメントは現在のコードを正確に反映**推奨**し、計画中の機能をリリース済みと記載しては**ならない**。  
7.2 バージョン番号は単一の情報源（例：`CHANGELOG.md`）を持ち、CI によって注入される**推奨**。  
7.3 ブランチ、Lite 版、移植版は上流との継承関係を**必須**で説明する。  
7.4 AI 生成の Markdown は、ブランチ名、リポジトリリンク、相対パスを手動で確認**推奨**。

## AI 生成声明テンプレート

新規プロジェクトは以下を `AI_DISCLOSURE.md` にコピーできます：

```markdown
# AI 生成声明

本プロジェクト（{{プロジェクト名}}）は、{{開発/リファクタリング/移植/トリミング}} において大規模言語モデルを使用しました。

**核心声明：コードの約 {{割合}} は AI によって直接生成され、人間の開発者は {{製品定義、レビュー、テスト、検収、リリース}} を担当しました。**

## AI が関与した部分
- `{{ファイルまたはモジュール}}`：{{生成内容と役割}}

## 人間が行った作業
- {{要件定義 / アーキテクチャ決定 / ビルドデバッグ / 実機テスト / 最終検収}}

## 既知の制限
1. {{AI は実機で実行できないため、プラットフォームの違いは人間の検証に依存する}}
2. {{プラットフォーム API の変更、エッジケース、セキュリティリスクなど}}

## ライセンス
本プロジェクトは {{ライセンス}} の下で公開されています。
```

## よくある質問

**AI 生成率は正確でなければなりませんか？**  
いいえ。保守的かつ誠実であるべきで、算定基準（行数、モジュール、機能単位）を明記してください。

**小規模プロジェクトでも開示が必要ですか？**  
推奨します。開示コストは低く、「説明できない」コストは非常に高いです。

**人間が一行もコードを書かなくても責任を負えますか？**  
はい。人間が要件定義、レビュー、検証、リリース決定を行った場合に限ります。責任はキー入力ではなく、意思決定と検収から生じます。

## 導入方法

プロジェクトで：

1. このファイルを `docs/AI-DEVELOPMENT-GUIDELINES.md` にコピーします；
2. `README.md` と `CONTRIBUTING.md` からリンクします；
3. [テンプレート](#ai-生成声明テンプレート) を使用して `AI_DISCLOSURE.md` を作成します；
4. PR テンプレートに「AI 関与の明記」「ターゲットプラットフォームでのコンパイル」「セキュリティ重要コードのレビュー」の 3 つのチェックを追加します。
